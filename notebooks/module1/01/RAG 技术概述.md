# RAG 技术概述

## 什么是 RAG？

### RAG 与其他技术对比

#### Fine-tuning（微调）与后训练（Post-training）

Fine-tuning 是在已经预训练好的模型上，使用特定任务、领域或风格的数据继续训练，使模型参数发生变化，从而更擅长某类工作。

后训练是预训练结束后的整体训练阶段，目标是让模型更好地遵循指令、进行推理、符合人类偏好并满足安全要求。Fine-tuning 通常是后训练中的一种具体方法，但两者不是同一层级的概念。

```text
预训练：形成通用语言能力
   ↓
后训练：塑造模型的整体行为
   ├── 指令微调（SFT）
   ├── 偏好与安全对齐（RLHF、DPO 等）
   └── 特定任务或领域 Fine-tuning
```

判断问题时可以区分三个层次：知识经常变化，优先考虑 RAG；回答格式或语气需要稳定统一，可以考虑 Prompt 或 Fine-tuning；模型整体的指令遵循、推理或安全能力不足，则更接近后训练问题。

#### RAG vs Fine-tuning

```text
Fine-tuning（知识内化）：
  训练数据 → 模型权重更新 → 新模型
  ↑
  耗时、昂贵、需重复训练

RAG（知识外挂）：
  知识库 → 检索 → 生成答案
  ↑
  实时、便宜、即插即用
```

选择建议：

- 使用RAG：当知识经常变化、需要高准确性时
- 使用Fine-tuning：当需要特定输出风格或格式时
- 组合使用：先Fine-tuning学习格式，再RAG提供知识

## 传统 RAG vs Agentic RAG

演进阶段：

```text
阶段1: Naive RAG（传统RAG）
  ↓
阶段2: Advanced RAG（高级RAG）
  ↓
阶段3: Agentic RAG（智能体RAG）
```

### Naive RAG（传统 RAG）

```text
用户问题
    ↓
[检索] → 向量数据库 → 相关文档
    ↓
[生成] → LLM → 答案
```

优点：

- 实现简单
- 易于理解
- 适合简单问题

缺点：

1. 检索质量依赖查询表达。问题：检索词不准确 → 检索效果差

2. 无法处理复杂问题。问题：需要多步推理 → 传统 RAG 难以处理

3. 检索结果可能不相关。问题：检索质量不稳定 → 答案质量差

### Advanced RAG（高级 RAG）

在检索前、检索中、检索后增加优化步骤。

```
用户问题
    ↓
[检索前优化]
  - 查询重写
  - 查询扩展
  - HyDE（假设文档嵌入）
    ↓
[检索]
  - 混合检索（向量+关键词）
  - 递归检索
    ↓
[检索后优化]
  - 重排序（Reranking）
  - 过滤
    ↓
[生成] → 答案
```

### Agentic RAG（智能体 RAG）

让 RAG 系统具备"智能"，能够：

- 自我反思：判断答案是否满意
- 动态调整：根据反馈调整策略
- 工具使用：主动调用多个工具
- 任务规划：将复杂问题分解

```
用户问题
    ↓
[智能体分析]
  - 问题理解
  - 任务分解
    ↓
[动态检索策略]
  - 判断需要什么信息
  - 选择合适的检索方法
    ↓
[迭代优化]
  - 评估答案质量
  - 不满意则重新检索
    ↓
[多步骤推理]
  - 整合多次检索结果
  - 进行逻辑推理
    ↓
最终答案
```

## RAG 技术栈选择

方案1：快速学习（推荐初学者）

```
框架：LlamaIndex
向量库：Chroma
LLM：GPT-3.5-turbo
嵌入：OpenAI text-embedding-3-small

优势：简单、快速、成本低
```

方案2：私有部署（企业应用）

```
框架：LlamaIndex
向量库：Qdrant
LLM：Qwen-72B（自托管）
嵌入：BGE-large-zh（开源）

优势：数据安全、无API费用、可控
```

方案3：大规模生产

```
框架：LlamaIndex
向量库：Milvus（分布式）
LLM：GPT-4（高质量）+ vLLM（加速）
嵌入：OpenAI text-embedding-3-large

优势：高性能、高质量、可扩展
```
